## Description

From docs/spikes/X4-jobs.md and X2-input.md (2026-10-31).
GOVERNOR (phase3): (1) one shared job per class is NOT viable — processes from different job hierarchies are rejected (error 5) and a job-free process can be pulled into an IDE's job; use one job per tree root (MyClean.Job.<class>.<rootPid>.<createTime>), optionally nested under a class parent job (nested caps compound). (2) Name-based crash re-adoption fails: the name vanishes with the last handle while members stay capped; keep a duplicate job handle in a second process (verified) or OBJ_PERMANENT as SYSTEM (unverified). (3) A job has exactly one completion port ever; re-adopted jobs must be polled (JobObjectBasicProcessIdList). (4) Global\ job names can be pre-created by any user — use a private namespace or verify SYSTEM owner. (5) Soft-limit NOTIFICATION_LIMIT floods (13,740 msgs/16 s): handle first, clear, re-arm from the 1 s loop. (6) PeakJobMemoryUsed unreliable after refused commits. (7) CPU hard cap is an average in ~0.6 s on/off cycles (job can be fully stopped ~0.3 s); keep build trees at below-normal priority too; 1 s loop aliases the cycle; ladder cap step 3 will cause visible pulses. (8) Ladder step 3 commit cap "current + 10%" breaks builds — use >= 25% headroom or soft limit only. (9) Resume only recorded (pid, createTime) pairs, exactly the recorded count. (10) Never allow breakaway; long-lived helpers (mspdbsrv, Gradle daemon, VBCSCompiler) keep per-tree jobs alive. (11) Kaspersky quarantines binaries statically importing NtSuspendProcess/NtResumeProcess — resolve via GetProcAddress, sign binaries, test signed builds under Kaspersky before M3/M1; tests must report "blocked by AV". Unverified: 7500 cap on idle machine, Global\ from session 0, OBJ_PERMANENT, elevated targets, Gradle.
INPUT WATCHDOG (phase1): probe the clipboard OWNER (GetClipboardOwner) too, not only the foreground window — an unanswering owner is the delayed-rendering fingerprint; record format IDs/names via GetUpdatedClipboardFormats, NOT sizes (sizes require opening the clipboard, forcing delayed rendering and reading content); timestamp with QPC at message receipt, never GetMessageTime (~16 ms); WM_INPUT may arrive after LL-hook delays (test T2 pending); add CPU/pressure state to every incident (new suspect: 100% CPU starving hook processes); F-029 ranking outdated (Keyboard Manager has no remaps, AnyDesk service-only, clipboard history off, viewer chain empty). Interactive tests T1-T4 need an owner-started session.
